# ml/ — the classifier as a standalone inference service

> **Scope, corrected 2026-09-04.** This directory packages the classifier for
> deployment. **Nothing here is deployed.** The hosted app is rules-only, the
> trained checkpoint was withdrawn on 2026-08-15, and the Hugging Face Space is
> private. The paragraph this header replaces described all three as live.

Takes the three-layer classifier (rules → `e5-small-v2` → SetFit) and wraps it
in interfaces that do not depend on Gmail, IMAP or the desktop app, with an
MLOps trail around the evaluation.

## What the numbers are, and which stage they belong to

**The rules layer scores 0.9791 macro-F1. The full cascade scores 0.9582.**
This file used to quote "0.98 measured on the v3 eval set" without naming a
stage, which is exactly the misattribution the root README exists to prevent:
*"The 0.9791 belongs to the rules layer. It is not a whole-system accuracy
figure, and the filenames actively mislead on this point."*

Measured by `scripts/cascade_gate.sh` on the committed 96-example v3 set and
recorded in [`docs/ML_PROMOTION_POLICY.md`](../docs/ML_PROMOTION_POLICY.md):

| configuration | macro-F1 | accuracy | misclassified |
| --- | --- | --- | --- |
| rules only | 0.9791 | 0.9792 | 2 of 96 |
| full cascade, checkpoint `setfit_model_20260306_175404` | 0.9582 | 0.9583 | 4 of 96 |

The learned layers make it **worse**, by −0.0210 macro-F1. That is recorded as
`comparison.verdict = behind_rules`, `promotable = false` in
`backend/data/evaluation/baseline_cascade_v3.json`, and it is why the deployed
app runs rules only. CI gates the rules figure at a 0.95 floor.

This file also used to publish a test count — "288 tests collected, 278
passing" — which was stale by roughly an order of magnitude and read as a suite
with ten failures. Counts live in
[`docs/readme-facts.json`](../docs/readme-facts.json), which is regenerated by a
command rather than typed, and are quoted in the root README where that checker
can see them.

## What each file is

| File | What it is |
|---|---|
| `service.py` | Standalone sync facade — `classify(subject, body) → {category, confidence, method, layers_consulted, latency_ms}`. No Gmail/IMAP/macOS coupling. |
| `track_run.py` | Runs the CI-identical eval, logs params/metrics/report to **MLflow**, registers `jobtracker-hybrid-classifier`, promotes to the `production` alias only past the 0.95 floor. Mirrors the run to **W&B** (offline). |
| `demo/app.py` | **Gradio** demo: paste an email → stage + confidence + three-layer decision trace. Synthetic examples only. |
| `bento_service.py` | **BentoML** REST service: `POST /classify`. |

**MLflow paths.** `track_run.py:72` points the tracking store at
`sqlite:///ml/mlflow.db`, which is git-ignored and created by the first local
run. The committed run artifacts live under [`mlruns/`](../mlruns/) at the
**repository root** — this file previously said `ml/mlruns`, and that path does
not exist. `mlruns/README.md` explains what those artifacts do and do not show.

Run everything with the backend venv (`backend/.venv311`), env
`JOBTRACKER_ENVIRONMENT=test`.

## Why the demo is not published

This section previously read "Pending owner logins (everything else is done)"
and gave two steps, the second of which was *"create the Space, push `demo/` +
the SetFit model dir"*. That instruction is now wrong in the most serious
direction available: it says to re-publish the checkpoint that was deliberately
withdrawn.

On **2026-08-15** the trained SetFit checkpoint and everything derived from it
were pulled from every public surface, because it was fitted partly on mail
read under Gmail's restricted `gmail.readonly` scope, which may not be
redistributed. The model repo and the Space are private; the ONNX exports are
deleted at `HEAD` and git-ignored. The root README's *"The published checkpoint
was withdrawn"* section is the full account, including the fact that the
artifacts remain reachable in git history.

**The route back to a publishable demo is a checkpoint trained on synthetic
data only** — the 400-case corpus at `backend/tests/corpus/` is the intended
source. No such retrain has been run, and no number in this file has been
re-recorded against one. `ml/browser/export_onnx.py` is unchanged and still
produces the artifact from a local checkpoint, so the tooling works; what is
missing is a checkpoint that can lawfully be published.

The W&B mirror is a separate and much smaller matter: it runs offline, and
`wandb login` followed by a rerun of `track_run.py` would give it a public
project link. That one is genuinely just a login.
