# JobTracker backend dependencies
# ===============================
#
# THE SHARED FLOOR LIVES IN ONE FILE, AND IT IS NOT THIS ONE (#704).
# `-r ../requirements.txt` pulls in the manifest Vercel actually installs for
# `api/index.py`. Everything below it is what the backend needs ON TOP: the
# desktop and ML stack that deliberately never ships to the cloud.
#
# Why the include rather than two hand-synced lists. The old arrangement had
# the same packages declared twice with no mechanism keeping them equal, and
# the root file said so in its own comment: "Nothing checks this mechanically."
# It drifted anyway — five shared packages by 2026-08-15, and THREE still
# disagreed after the 2026-09-02 sync (#705):
#
#     sqlmodel            root >=0.0.39   here >=0.0.14   (25 releases apart)
#     sqlalchemy[asyncio] root >=2.0.52   here >=2.0.25
#     cryptography        root >=50.0.0   here >=50.0.0,<51
#
# A pip dry-run resolved production to sqlmodel 0.0.42 and the suite to 0.0.32,
# so the suite could go green against a version production never runs. A gate
# asserting the two files' floor STRINGS match would not have caught that: the
# floors can be identical while a transitive cap in the dev stack still pulls
# the resolved version down. The include makes the conflict physical instead —
# there is one floor, and if the dev stack cannot satisfy it the install fails
# loudly rather than resolving quietly to something else.
#
# So: a shared package's floor is raised in ../requirements.txt and nowhere
# else. Only genuinely backend-only packages belong below.
-r ../requirements.txt

# -----------------------------------------------------------------------------
# Backend-only: server and desktop runtime
# -----------------------------------------------------------------------------
# Excluded from the cloud manifest on purpose — see its "DO NOT add" list.
# websockets and aiosqlite are not needed on Vercel; keyring is macOS Keychain
# only and is replaced there by Fernet encryption.
uvicorn[standard]>=0.52.4     # ASGI server with uvloop
websockets>=17.1              # WebSocket support for real-time sync updates
aiosqlite>=0.22.1             # Async SQLite driver (desktop/tests)
alembic>=1.19.1               # DB migrations (owns schema on Postgres)
keyring>=25.7.0               # Secure credential storage (macOS Keychain)

# -----------------------------------------------------------------------------
# Backend-only: the heavy ML stack
# -----------------------------------------------------------------------------
# ~800 MB with torch. This is the whole reason the two manifests differ: it
# blows Vercel's Python Function size budget many times over.
# These three move together. `transformers` carried `>=4.40,<5` and that cap was
# the sole life support for four Dependabot alerts (3 high, 1 moderate) whose
# every fixed version is 5.x -- no dependent asked for it, so it excluded the
# patches by construction (#746). Nothing under `backend/` imports
# `transformers` directly; the only direct import in the tree is
# `ml/browser/export_onnx.py:28`.
#
# `setfit` is here at 1.2.0 rather than 1.1.3 because the pairing MATTERS and
# the failure is silent: under transformers 5.x, setfit 1.1.3 raises
# `ImportError: cannot import name 'default_logdir'`, and the hybrid evaluation
# then scores ~0.979 having loaded no model at all -- the exact degradation
# `tests/test_evaluate_classifier_layer_guard.py:20` records. A floor of 1.1.3
# still permits that combination, so raising `transformers` alone would ship it.
#
# `sentence-transformers` moves to 6.x because that is what actually resolves:
# ST 6.0.1 declares `transformers>=5.0.0,<6.0.0`, so transformers 5 forces it,
# which in turn pulls `huggingface-hub>=1.3.0`. Naming it here rather than
# letting two majors arrive unannounced through a transitive.
#
# Verified by two clean resolves differing in one line.
#
# THE CASCADE EVIDENCE THIS NOTE USED TO CITE IS NOT REPRODUCIBLE AS WRITTEN.
# It read "`scripts/cascade_gate.sh --mode hybrid --hybrid-profile full`
# returns BIT-IDENTICAL predictions on 5.16.1 and on 4.57.6". That script takes
# only `--checkpoint` / `--update-baseline` / `--help` and hardcodes the mode;
# the quoted invocation exits 2 with `unknown argument: --mode`, so whatever
# produced that claim, it was not the command named here. The claim may well be
# true -- the underlying `evaluate_classifier` CLI does accept those flags --
# but it is recorded as UNVERIFIED rather than left looking checked. The
# runnable form is `PYTHON=<repo>/backend/.venv311/bin/python
# ./scripts/cascade_gate.sh`, which passes (exit 0, accuracy 0.9688).
#
# And the suite DOES import the ML stack -- `test_a_null_field_is_an_empty_one.py`
# constructs a `HybridClassifier`. It imports it; it does not grade it. The
# original "never imports" was wider than the truth, which is the more useful
# statement: a green suite is not evidence about these three pins.
sentence-transformers>=6.0.0  # Sentence embeddings (loads e5-small-v2)
transformers>=5.10.0          # HuggingFace transformers (see the note above)
setfit>=1.2.0                 # Few-shot text classification; 1.1.3 breaks on 5.x
scikit-learn>=1.9.0           # ML utilities (cosine similarity, etc.)
numpy>=2.4.6                 # Numerical operations, embedding serialization

# -----------------------------------------------------------------------------
# Upper bounds retained here, on packages whose FLOOR comes from the root file
# -----------------------------------------------------------------------------
# pip intersects a constraint given in an included file with one given here, so
# this narrows the inherited `cryptography>=50.0.0` without restating the floor.
# Verified: the pair resolves to cryptography 50.0.1.
# The comment here used to read "keeps mlflow<49 happy". IT DOES NOT AND CANNOT:
# mlflow 3.14.0 declares `cryptography<49,>=43.0.0`, and `<51` does not enforce
# `<49`. `pip check` says so out loud. Nor could it be fixed by writing `<49` --
# the inherited floor is `>=50.0.0`, so that pair is unresolvable.
#
# The violation is nominal and INHERITED, not caused here: the parent already
# resolved cryptography above 49, and mlflow is declared in NO manifest in this
# repository (only `ml/track_run.py` imports it, and there is no
# `ml/requirements.txt`). It was exercised at 50.0.1 -- a run logged to a
# scratch sqlite store -- and works.
#
# So the cap is kept for what it actually does: refuse an unreviewed major.
cryptography<51               # refuses cryptography 51.x; floor is in ../requirements.txt
